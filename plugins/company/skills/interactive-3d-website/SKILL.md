# インタラクティブ 3D Web サイト（ChatGPT + Higgsfield）

**目的**: 「製品を 360 度回して、パーツをクリックすると説明が出て、スクロールでカメラが寄る」ような
3D Web サイトを、コードを 1 行も手で書かずに **ChatGPT（GPT-6 Astra）に組ませ、素材は Higgsfield に作らせ、ライブ URL まで届ける**。

役割分担はこう覚える。

```
Higgsfield  = 素材工場   … 3D モデル（GLB）、リファレンス画像、動画ループ、テクスチャ、カバー画像
GPT-6 Astra = 建築家＋大工 … 仕様を決め、Three.js でサイトを組み、動かして直し、公開する
あなた（Claude） = 現場監督 … 体験を設計し、プロンプトを書き、QA し、公開経路を選ぶ
```

Astra はコードを書けるが「何を見せると刺さるか」「どのモデルで素材を作るか」「どこで公開するか」は
人が決めないと平凡な結果になる。このスキルはその判断を先に固めてから手を動かす。

---

## いつ使うか

- `/interactive-3d-website` を実行したとき
- 「3D サイト」「回せる LP」「分解図を Web で」「Three.js / WebGL」「Higgsfield で 3D」「Sites で公開」と言われたとき
- cc-company の運営モードで、マーケティング / クリエイティブ部署に 3D コンテンツや WebGL の依頼が来たとき

---

## 全体像

```
Step 0  ヒアリング（1回だけ）
   │
Step 1  体験パターンを決める（何を、どう触らせるか）
   │
Step 2  素材を Higgsfield で作る（リファレンス画像 → GLB → 動画・カバー）
   │
Step 3  Astra にサイトを組ませる（仕様書＋プロンプトの型）
   │
Step 4  検証する（QA チェックリスト）
   │
Step 5  公開する（ChatGPT Sites / Higgsfield website / 自前ホスティング）
   │
Step 6  チャットで直し続ける
```

**Step 1 と 2 を飛ばして Step 3 に行かない。** 素材（GLB）が無い状態で Astra に「3D サイト作って」と言うと、
プリミティブ（箱や球）で組んだデモが返ってくる。見せたいモノの GLB を先に持つことが品質の 8 割を決める。

---

## Step 0: ヒアリング（1回だけ）

`AskUserQuestion` で **1 回にまとめて** 聞く。二度目のヒアリングはしない。足りない情報は Step 1 の表からこちらが提案して埋める。

1. **何を見せたいか** —— 製品（実物あり / 写真あり / まだ無い）、空間・建築、キャラクター、データや仕組みの可視化
2. **どう触らせたいか** —— Step 1 の A〜E から選んでもらう（迷っていれば A を推す）
3. **作業環境** —— (a) ChatGPT デスクトップ + Higgsfield プラグイン、(b) Higgsfield Supercomputer、(c) Claude Code / Cursor + Higgsfield CLI
4. **手持ちの素材と制約** —— 既存の 3D データ（GLB / FBX / CAD）、製品写真、ブランド色・フォント、公開先の希望、納期

環境ごとのセットアップ手順は `references/setup.md`。ChatGPT で使う場合は
**Work モードで Astra を選び、ツールメニューで Higgsfield を ON にする** ところまで確認してから進む。

## Step 1: 体験パターンを決める

| # | パターン | 向く用途 | 必要な素材 | 実例（`references/case-studies.md`） |
|---|---|---|---|---|
| A | **ショールーム** — ドラッグで回転、ホイールでズーム、色 / 素材の切替 | 製品 LP、EC の商品ページ | GLB 1 体 + 背景 / 環境光 | Orbital Core Showcase |
| B | **分解ビュー** — スライダーでパーツが離れ、クリックで 1 パーツを単独表示＋説明 | 機構の説明、教育、修理・組立ガイド | パーツ分割された GLB（名前付きメッシュ） | Model X Studio、Microduck Assembly Lab |
| C | **スクロール・ジャーニー** — スクロール量でカメラが進む / 生成した映像が再生される | ブランドサイト、ローンチ LP、ストーリーテリング | GLB + カメラパス、または 15 秒程度の一続きの映像 | Higgsfield の scroll-scrub 方式 |
| D | **歩ける世界・ジオラマ** — 小さな世界を見下ろし、ランドマークへ飛ぶ | 施設案内、街・イベント、ゲーム的な体験 | シーン GLB（Blender 経由が多い） | Moonlit Forge、Hangzhou in Three.js |
| E | **動くキャラクター** — リグ付き GLB が待機 / 手振りなどのアニメーションをする | マスコット、採用サイト、ゲームの告知 | リグ＋アニメーション付き GLB | Higgsfield 公式の 9 ステップ・プロンプト |

判断の目安:

- 「製品を売る」なら **A**、機能や中身を語る必要があれば **A + B**。
- 「世界観を語る」なら **C**。3D モデルを起こす予算が無いときも C は **生成映像だけ**で成立する（VEYRA の事例は 3D モデルを使わず映像トランジションで作っている）。
- **B は GLB の作り方で決まる。** パーツごとに分かれたメッシュが無いと「クリックで分離」は実装できない。既存 CAD / Blender データがあるなら B、写真から生成した GLB は 1 メッシュになりがちなので A か C に寄せる。

決めたら 1 行で書く: 「**{見せるモノ} を {パターン} で、{公開先} に。主役の操作は {1 つ}**」。主役の操作は 1 つに絞る。全部入りは全部が薄くなる。

## Step 2: 素材を Higgsfield で作る

詳細（モデル別のパラメータ、CLI コマンド、軽量化）は `references/3d-assets.md`。ここでは順番と判断だけ。

### 2-1. リファレンス画像を先に作る

写真が無い / まだ製品が無いときは、Higgsfield の画像モデル（GPT Image 2.5 / Nano Banana 2）で
**白背景・同一スケール・正面 / 側面 / 背面 / 上面の 4 面図**を 1 枚のシートとして作る。
3D 化モデルは複数枚の参照があるほど形が安定する（1〜4 枚まで渡せる）。

### 2-2. GLB を作る（用途で 5 モデルを使い分ける）

| 欲しいもの | Higgsfield のモデル | 入力 |
|---|---|---|
| 写真 / 4 面図から製品の 3D | `multi_image_to_3d`（1〜4 枚）/ `image_to_3d`（1 枚） | 画像 |
| 文章だけから 3D | `tripo_3d`（Text to 3D） | プロンプト |
| 写真の中の物体を切り出して 3D | `sam_3_3d`（3D Objects） | 画像（＋対象を示すプロンプト） |
| キャラクターにリグ・アニメーション | `image_to_3d` の `enable_rigging` / `enable_animation`、既存 GLB には `3d_rigging` | 画像 or GLB の URL |

どのモデルも **結果は GLB**（メッシュ＋テクスチャ＋必要ならスケルトン / アニメーション）。GLB は Three.js でそのまま読める。

Web 用の勘所:

- **テクスチャは必ず付ける**（`should_texture true`、質感が要るなら `enable_pbr true`）。素のメッシュはブラウザで安っぽく見える。
- **ポリゴン数は抑える**（`target_polycount` を 3〜10 万程度から）。スマホで回すページに 100 万ポリゴンは載らない。
- 製品は `symmetry_mode auto`、キャラクターは `pose_mode a-pose` から始める。
- 出来上がった GLB は **必ず一度ブラウザのビューアで開いて確認**する（穴、裏返った面、テクスチャのにじみ）。だめなら参照画像を足して再生成。手直しより作り直しが速い。

### 2-3. 追加素材

- **スクロール映像（パターン C）**: Seedance 2.5 で **15 秒程度の一続きのショット** 1 本。カット割りせず 1 本にすると継ぎ目が出ない。
- **カバー / OG 画像**: 公開前に必ず作る。SNS で共有されたとき空のカードにならないため。
- **環境光**: Three.js 側の `RoomEnvironment` で足りることが多い。HDRI を用意するのはそれで足りないときだけ。

ChatGPT のプラグイン経由なら、これらは会話で「Higgsfield で …を作って」と頼めば Astra がプラグインを呼ぶ。
Claude Code / Cursor なら `higgsfield generate create <model> … --wait` を叩く（`references/3d-assets.md`）。

## Step 3: Astra にサイトを組ませる

### 3-1. プロンプトの型

うまくいく指示には共通の型がある。**出力の形を名指しし、置き場所を名指しし、公開前にプレビューを求める。**

```
{何を} を {Three.js / React Three Fiber} で作って。
素材: {model.glb（Higgsfield で生成）、poster.jpg、…}
操作: {主役の操作 1 つ}＋{補助の操作 1〜2 つ}
見た目: {ブランド色、余白、フォント、暗い/明るい}
スマホ: {タッチで回転、ピンチでズーム、軽量化}
出力先: {Sites に "{slug}" として / このフォルダに index.html として}
公開の前にプレビュー URL を見せて。
```

英語プロンプトの完成例と、パターン A〜E それぞれの雛形は `references/prompts.md`。

### 3-2. 仕様書を先に 1 枚渡す

長い会話で仕様が散らばると Astra は前の決定を落とす。**最初のメッセージに「3D サイト・ビルドシート」（下の成果物フォーマット）をそのまま貼る。**
仕様変更のときもビルドシートを直して貼り直す。

### 3-3. Astra に守らせる実装の要点

`references/interactions.md` に Three.js のパターン（GLB 読み込み、オービット、クリックでパーツ分離、分解スライダー、スクロール連動カメラ、軽量化）をまとめてある。
Astra は自力で組めるが、次の 5 点は最初の指示に必ず入れる。**後から足すと作り直しになる。**

1. **ローディング表示**（GLB は数 MB〜数十 MB。進捗バーが無いと「壊れている」と思われる）
2. **モバイル対応**（タッチ操作、`devicePixelRatio` の上限、ポリゴン数）
3. **フォールバック**（WebGL が使えない環境には静止画のポスターを出す）
4. **パーツ名で操作する設計**（分解ビューはメッシュ名をキーに説明文を引く。名前が無い GLB は先に Blender 等で命名）
5. **ページ本文は HTML のまま**（見出し・説明文を Canvas に描かない。検索・共有・アクセシビリティのため）

## Step 4: 検証する

公開前に **実機で** 次を見る。1 つでも落ちていたら Step 3 に戻す。

- [ ] 初回表示 3 秒以内に「何か」が見える（ポスター or 進捗）。GLB 合計サイズは目安 10〜20 MB 以下
- [ ] マウス: ドラッグ回転 / ホイールズーム / クリック選択が意図どおり。慣性が強すぎない
- [ ] スマホ: 1 本指回転、2 本指ズーム、ページスクロールと 3D 操作が喧嘩しない
- [ ] 分解ビュー: 全パーツが元の位置に戻る。単独表示の解除手段（背景クリック / ESC / 戻るボタン）がある
- [ ] スクロール連動: 最下部まで行ってカメラが破綻しない。`prefers-reduced-motion` で演出を弱める
- [ ] 見た目: 裏返った面、黒くつぶれた影、白飛びしたテクスチャが無い。環境光が入っている
- [ ] 本文と OG: タイトル / 説明文 / カバー画像が入っている。共有プレビューが空でない
- [ ] 権利: 使った 3D 素材・写真・フォントの利用条件を確認した

## Step 5: 公開する

| 経路 | 向く場面 | 手順の要点 | 詳細 |
|---|---|---|---|
| **ChatGPT Sites** | ChatGPT で作った流れのまま最速で URL を出す | Astra に「Sites に公開して」。先にプレビューを見る。URL は `*.chatgpt.site` 形式 | `references/publish.md` |
| **Higgsfield website（CLI）** | Claude Code / Cursor で作業中。フルスタック（DB / ストレージ）や独自サブドメインが欲しい | `higgsfield website create --type website --subdomain <slug>` → `repo-access` → 編集 → `deploy` | `references/publish.md` |
| **自前ホスティング** | 既存サイトに組み込む、独自ドメイン、CI で回す | 静的ファイル（HTML / JS / GLB）を Cloudflare Workers・Vercel・GitHub Pages 等に置く | `references/publish.md` |

**ChatGPT では Higgsfield の Website Builder スキルは使えない**（Higgsfield のヘルプセンター記載）。ChatGPT で完結させるなら「素材 = Higgsfield、サイトと公開 = Astra + Sites」の分担になる。

---

## Step 6: チャットで直し続ける

公開後の修正は、会話でそのまま頼む（「カメラの初期位置をもう少し斜め上から」「説明パネルをブランド色に」）。
そのとき **ビルドシートも更新して貼り直す**。1 か月後に別の人が引き継げる状態を保つのが目的。

改善の優先順位は「初回表示の速さ → 主役の操作の気持ちよさ → 見た目 → 追加機能」。

## 注意事項

- **クレジット**: Higgsfield の生成（特に動画・3D）はクレジットを消費する。動画は本数を絞り、3D は参照画像を整えてから 1 発で決める
- **権利**: 実在製品・キャラクター・他社ロゴの 3D 化は権利者の許諾が要る。既存の 3D 素材を使うときはライセンスをビルドシートに書く
- **環境の差**: GPT-6 Astra は ChatGPT の Work モード（Plus は Work と Codex のみ）で使える。UI の文言や配置は変わるので、`references/setup.md` の手順で迷ったら「Higgsfield プラグインが ON になっているか」だけ確かめて進む
- **技術の変化**: このスキルはドキュメントの形で読めた一次情報だけを土台にしている。何を根拠にしたかは `references/sources.md`。合わない点があればそこから当たり直す
